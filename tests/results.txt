Other things i tried while in there

1. native x86-64 output (mlonc file.mlon -o out, no --jit) builds and
   links a dynamic ELF fine, but external calls silently do nothing.
   compiled match_1 to a real binary, it ran, exited 0, printed nothing.
   same for a 3 line printf hello. a return-only main (return 42) worked
   and the exit code came through. so imports like printf/strlen are dead
   in the native path right now. worth a look before calling rc1 done, or
   at least a note in the docs that programs using libc should use --jit.

2. i386 compile-only (mlonc -m32 -c file.mlon -o x.o) fails on all 10 with
   "fatal error: internal: relocation references unknown symbol printf".
   pretty sure that is expected since AneoC objects are freestanding and
   there is no libc to resolve against, just leaving it here for the record.
   did not count these as failures.

3. string_1 prints first letter as 112 rather than 'p'. looked at the test,
   it checks word[0] == 'p' which passed, so it is just %v rendering a char
   as its int value. not a bug, just noting it so nobody trips on it later.
